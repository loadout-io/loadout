# T-208 — Każdy bieg ma jawny limit kosztu i bezpieczny próg dysku

Bieżący produkcyjny run wystartował bez budżetu, a ukończone kroki zgromadziły bardzo wysoki
szacunek kosztu. Równoległe worktree zajęły około 12 GiB głównie przez osobne Cargo `target`.
Nie wprowadzamy arbitralnego quota, które przerwie poprawny build. Start ma jednak wymagać
świadomej decyzji finansowej, a brak miejsca ma być odmową przed pierwszym procesem.

**Zależy od:** T-155, T-204, T-206 i T-207.

**Tryb:** pełny Harness, bo aktywny próg dysku i budżetu może zatrzymywać grupę procesu.
Jedyne wejście to `./ship-task.sh T-208 --agent codex --reviewer codex`; obowiązują uczciwe
`before`, quick/full, read-only review, najwyżej jedna repair i pojedyncze `integrate.sh`.

**Read first:** `AGENTS.md` niezmienniki 6, 10, 11, 13, 19 i 24 · `tasks/T-94.md` ·
`src-tauri/src/commands/{run,triggers}.rs` · `src-tauri/src/ipc.rs` · frontendowy Start i feed.

## AC-1 Brak limitu jest świadomą decyzją, nie domyślnym `None`
check: cargo test --test t208_run_has_explicit_resource_envelope
expect: (\d+) passed

Manualny Run i `/ask` niosą albo dodatni finite `budget_usd`, albo osobny jawny wybór
`unlimited: true`; brak obu jest odmową przed rezerwacją workspace i procesem. Trigger zawsze
ma finite budget zapisany w configu — nie może wybrać unlimited bez człowieka. Wartość i tryb
trafiają do planu oraz receipt. Enforcement używa poprawionych liczników T-207. Gdy znany
streaming spend osiąga finite budget, normalna ścieżka Stop z T-201 kończy grupę, a receipt
zapisuje resource limit jako wartość, nie błąd transportu. Model/tier bez dowiedzionej ceny nie
może obiecać finite enforcementu: Start prosi o zmianę modelu albo jawne `No limit`.

Przed utworzeniem izolacji backend mierzy wolne miejsce na właściwym filesystemie. Jawny twardy
próg produkcyjny daje widoczną odmowę przed pierwszym worktree. Jeden bounded monitor per run
sprawdza ten sam filesystem także podczas pracy: próg miękki daje jedno ostrzeżenie, a zejście
poniżej twardego progu anuluje aktywne kroki przez normalny Stop T-201, zachowuje osiągalną pracę
i zapisuje `resourceLimit: disk`. Nie usuwa plików, nie zgaduje ownershipu i nie obiecuje byte
quota systemu plików; gwarancją jest jawny floor oraz maksymalny interwał reakcji testowany przez
sterowany zegar.

## AC-2 Człowiek widzi limit, bieżący koszt i presję dysku
check: npx --no-install vitest run src/sections/run/t208-resource-envelope-is-visible.test.tsx
expect: (\d+) passed

Prawdziwy Start nie uruchamia bez wybranego limitu albo potwierdzonego `No limit`. Trigger editor
wymaga finite limitu. Podczas biegu jedno miejsce pokazuje budżet, znany spend albo `Unavailable`
oraz ostrzeżenie o przestrzeni; po twardym progu pokazuje, że Loadout zatrzymał bieg, aby zachować
wolne miejsce. Nie pokazuje fałszywych USD, nie mnoży bannerów per krok i nie używa żargonu o
worktree.
