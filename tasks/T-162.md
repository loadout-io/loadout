# T-162 — NOW pokazuje wyłącznie pracę, która trwa

Model feedu dodaje dziś agenta do `doing` przed rozpoznaniem rodzaju wiersza. W efekcie także
`stepState: pending`, `succeeded`, `failed`, `cancelled` i `skipped` tworzą lub zostawiają
wiersz w NOW. Zakończone kroki z długiego workflowu zajmują ekran aż do zejścia całego biegu,
a spóźniona linia potrafi ponownie pokazać pracę, która już się skończyła.

NOW jest jednym miejscem odpowiedzi na pytanie „kto pracuje teraz”. Historia i rail zachowują
pełny zapis; to zadanie nie usuwa z nich agentów ani nie tworzy drugiego panelu stanów.

**Zależy od:** T-156. T-156 najpierw domyka lifecycle tego samego `feed/model.ts`.

## Uczciwe `before`

Oba targety istnieją i zbierają się przed `./verify.sh before`. Czysty test modelu podaje
prawdziwe `Incoming`; browserowy montuje prawdziwy ekran. Przed poprawką padają na obecności
zakończonego wiersza albo geometrii, nie na braku modułu, fixture, Chromium czy testów.

## AC-1 Stan kroku jest jedynym właścicielem jego obecności w NOW
check: npx --no-install vitest run src/sections/run/feed/t162-finished-steps-leave-now.test.ts
expect: (\d+) passed

Target prowadzi kilku agentów przez `pending → ready → running → succeeded|failed|cancelled|skipped`.
Do NOW wchodzi agent dopiero przy żywej pracy; terminalny stan usuwa dokładnie jego wiersz,
nie rusza pozostałych agentów i nie kasuje historii. Spóźnione `thinking`, tekst, narzędzie ani
powtórzony terminalny stan nie wskrzeszają zakończonego kroku. Nowy jawny `running` tego samego
agenta w kolejnym biegu może go pokazać ponownie. Nieznany przyszły stan jest ignorowany bez
wywalenia feedu.

## AC-2 Wielu aktywnych agentów nie zabiera feedu ani composera
check: npx --no-install vitest run e2e/tests/t162-now-preserves-feed-and-composer.spec.ts
expect: (\d+) passed

Chromium przy `1100 × 700` pokazuje osiem równolegle pracujących agentów. NOW ma stały budżet
wysokości około czterech wierszy i własny pionowy scroll; historia oraz pole `Command line`
pozostają widoczne. Po terminalnych stanach lista kurczy się bez pustego zarezerwowanego panelu.
Test mierzy bounding boxy i scroll prawdziwego DOM, nie nazwy klas. Rail nadal zachowuje pełny
roster biegu.
