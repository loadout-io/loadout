# T-165 — Refleksja mówi, co robi i co zrobiła

Checkbox `Learn from this run` nie wyjaśnia dziś ani kiedy rusza, ani gdzie trafia wynik.
Po biegu `run.json` ma już receipt (`ran`, `kept`, `discardedAgain`,
`dropped_without_reason`, `cost_usd`), lecz historia go nie czyta. Człowiek widzi więc koszt
i sugestie w Memory bez związku z wyborem, który zaznaczył przed Startem.

To zadanie nie tworzy etapu workflow, nowego modelu stanów ani automatycznej pamięci. Zachowuje
obecną semantykę: po udanym kroku z użytecznym handoffem Loadout może wykonać najwyżej jedną
prywatną turę tylko do odczytu; jej wynik trafia jako `Suggested` do Memory i wymaga decyzji
człowieka. Wyłączony wybór daje zero tur. Zmieniamy opis i pokazujemy istniejący receipt.

Widoczna nazwa wyboru to `Review this run for reusable notes`. Obok stoi krótki tekst:
`After a successful run, Loadout may use one private read-only turn. Suggestions stay in Memory
until you approve them.` UI jest po angielsku, a szczegóły modelu i limitu pozostają w jednym
miejscu, bez surowych nazw pól z drutu.

## Uczciwe `before`

Rustowy target czyta prawdziwe stare i nowe `run.json`. Browserowy target klika prawdziwy
checkbox i prawdziwe drogi Start. Test panelu montuje historię przez produkcyjny store/IO.
Porażki są na niewidocznym objaśnieniu albo zgubionym receipcie, nie na braku modułu.

## AC-1 Historia przewozi istniejący receipt i zachowuje stare biegi
check: cargo test --test t165_reflection_receipt_reaches_history
expect: (\d+) passed

`read_run` mapuje receipt bez zgadywania: `ran`, `kept`, `discardedAgain`,
`dropped_without_reason` i rzeczywisty `cost_usd`. Brak całego pola `reflection` w starszym
`run.json` daje jawny brak receiptu, nie syntetyczne `ran:false`, i nie gubi kroków, handoffów,
gałęzi ani stanu. Nieznane przyszłe pola są ignorowane.

## AC-2 Wybór wyjaśnia warunki i nadal steruje każdą drogą Start
check: npx --no-install vitest run e2e/tests/t165-reflection-is-explained.spec.ts
expect: (\d+) passed

Chromium widzi `Review this run for reusable notes` i całe objaśnienie przy kontrolce, domyślnie
zaznaczone. Manual Run, `/run` i Run z edytora wysyłają dokładnie jedno `reflectionEnabled`
zgodne z widocznym stanem także po remouncie; brak dodatkowego IPC w cichym oknie. Wyłączenie
daje `false`, ponowne włączenie `true`. Test aktualizuje zamrożoną drogę T-126 zamiast dokładać
drugi, sprzeczny oracle starego napisu.

## AC-3 Otwarty bieg mówi, czy i z jakim skutkiem refleksja zaszła
check: npx --no-install vitest run src/sections/run/past/t165-reflection-outcome-is-visible.test.tsx
expect: (\d+) passed

Prawdziwy panel historii pokazuje dokładnie jeden zwarty wiersz `Reusable notes`:

- brak receiptu: `This older run has no reusable-notes receipt.`;
- `ran:false`: `No reusable-notes review ran.`;
- `ran:true, kept:0`: `No reusable notes were added.` plus liczba odrzuconych lub niepełnych
  sugestii, jeśli jest dodatnia;
- `ran:true, kept:N`: `Suggested N notes in Memory` i koszt, jeśli istnieje.

`kept` nigdy nie jest nazywane approved ani learned. Przycisk/odnośnik do Memory istnieje tylko,
gdy `kept > 0`, działa i nie tworzy drugiej kopii sugestii. Surowe klucze, vendor i model nie
trafiają na ekran.
