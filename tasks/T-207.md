# T-207 — Receipt mówi prawdę o wykonaniu, pochodzeniu i koszcie

Ostatnia diagnostyka pokazała trzy różne fakty zlane w jedno `complete`: terminalny
`startFailed`, niekompletne evidence i stary katalog bez `run.json`. Jednocześnie receipt nie
wiąże biegu z buildem Loadout ani stanem projektu, a liczniki Codex App Servera nie są filtrowane
po aktywnym thread/turn. Ten task naprawia prawdę danych; nie sprząta historii i nie ustala
budżetu startu — to robi T-208.

`./verify.sh quick`, read-only diff review i pojedyncze `integrate.sh`.

## AC-1 Terminalność, kompletność evidence i provenance są osobnymi faktami
check: cargo test --test t207_receipt_truth_and_provenance
expect: (\d+) passed

Produkcyjne drogi Run i `/ask` zapisują osobno `settled`, `evidence_complete`,
`process_started` i `death_proof_applicable`. `start -> Err` bez procesu jest terminalne, ma
`process_started: false` i nie wymaga fikcyjnego death proof. Started process nie może być
terminalny bez `death_proof: true` albo `cleanup-needed`. Stare receipt bez pól czytają się jako
`unknown`, nigdy jako zmyślone `false`.

Diagnostyka nie zamienia brakującego albo uszkodzonego `run.json` w pusty normalny bieg. Zwraca
typowany legacy/recovery problem z bezpieczną ścieżką. Receipt zdrowego biegu zapisuje build SHA
Loadout albo jawne `unknown`, wersję aplikacji, project base HEAD i dirty fingerprint bez bajtów
plików. Current-SHA smoke może więc porównać dowód, nie deklarację operatora.

## AC-2 Tokeny i koszt należą wyłącznie do aktywnej tury
check: cargo test --test t207_codex_usage_is_scoped
expect: (\d+) passed

Atrapa App Servera wysyła wiele `thread/tokenUsage/updated`: aktywny thread/turn, spóźnioną
aktualizację poprzedniej tury, replay, reset i kumulatywne `last`/`total`. Produkcyjny decoder
liczy wyłącznie monotoniczną deltę aktywnej tury i nie dodaje ponownie wartości kumulatywnej.
Receipt zachowuje rozdzielone input/output/cached i zawsze zapisuje znany `spent_usd`, również
bez budżetu. Gdy semantyka eventu albo tabela cenowa nie jest dowiedziona dla modelu/tieru,
`cost_usd` jest `null` z nazwanym powodem, nie zgadywaną kwotą.

## AC-3 Człowiek widzi, że historyczny dowód jest niepełny
check: npx --no-install vitest run src/sections/run/past/t207-receipt-problems-are-visible.test.tsx
expect: (\d+) passed

Target przechodzi przez produkcyjne `readHistory`/store i renderuje prawdziwy panel History dla
katalogu bez `run.json`, uszkodzonego receipt, `evidence_complete: false` oraz
`cleanup-needed`. Każdy wiersz i otwarty bieg pokazują jedno bezpieczne angielskie zdanie
odróżniające te fakty; brak receipt nie wygląda jak pusty poprawny run, a brak death proof dla
`process_started: false` nie jest fałszywą awarią procesu.

Zdrowy bieg nadal pokazuje kroki, handoffy i gałęzie. Test montuje panel przez produkcyjny
store/IO i asertuje markup, nie sam formatter ani ręcznie podany prop, którego caller nie ma.
