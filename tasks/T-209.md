# T-209 — Historyczne izolacje są odzyskiwane tylko z dowodem

T-152 zapobiega nowym sierotom przygotowania, ale obecny workspace ma stare katalogi bez
`run.json` oraz terminalne runy z zachowanymi worktree. Brak automatycznego sprzątania jest
bezpieczniejszy od zgadywania, lecz aplikacja produkcyjna potrzebuje deterministycznego recovery
dla zasobów, których ownership potrafi udowodnić.

Task nie kasuje raw evidence, handoffów ani rozmów. Nie usuwa też `unknown` i nie interpretuje
braku procesu jako zgody na deletion.

**Zależy od:** T-153, T-155, T-201 i T-207.

**Tryb:** pełny Harness. Prawdziwe repo Git, fault-injection, czerwone `before`, quick/full,
read-only review, najwyżej jedna repair i pojedyncze `integrate.sh`.

**Read first:** `AGENTS.md` niezmienniki 4, 6, 19, 21 i 24 · `tasks/T-95.md` ·
`src-tauri/src/commands/{isolate,reconcile}.rs` · `src-tauri/src/workspace.rs` · historia runów.

## AC-1 Recovery rozróżnia cleanup-safe, retained i unknown
check: cargo test --test t209_historical_isolation_recovery_is_safe
expect: (\d+) passed

Prawdziwe tymczasowe repo zawiera: terminalny run z death proof i czystym Loadout-owned worktree,
terminalny run z osiągalną pracą, cleanup-needed z żywą grupą, katalog bez `run.json`, symlink,
obcy worktree oraz nieosiągalny branch. Produkcyjny startup/reconcile automatycznie sprząta tylko
pierwszy przypadek. Praca pozostaje osiągalna; retained i unknown dostają typowany powód oraz
bezpieczną ścieżkę, a żadna ścieżka nie wychodzi poza kanoniczny `.loadout/runs`.

Fault-injection przed każdym usunięciem i zapisem receipt zostawia stan, który następny restart
klasyfikuje tak samo. Cleanup nigdy nie dotyka ludzkiego tracked/untracked WIP, raw evidence,
handoffów ani branchy bez dowodu osiągalności. Powtórzenie jest idempotentne.

## AC-2 Po rozliczeniu nowego biegu worktree i presja dysku wracają do uczciwego stanu
check: cargo test --test t209_settled_run_releases_isolation_storage
expect: (\d+) passed

Setki małych cykli oraz jeden run z dużym ignored `target/` kończą się bez zarejestrowanych
worktree i bez zachowanych ignored build outputs, jeśli branch nie niesie pracy. Gdy branch
niesie zmianę, pozostaje osiągalny zgodnie z T-153. Receipt zapisuje wynik cleanup; błąd nie
udaje sukcesu i pozostaje adresowalny do Retry po T-155.

`target/` jest usuwany wyłącznie jako zawartość całego worktree utworzonego przez Loadout, gdy
kanoniczna ścieżka, branch, run UUID i marker creation receipt nadal pasują, worktree nie istniał
w baseline przed próbą, a Git potwierdza brak pracy do zachowania. Task nigdy nie usuwa samego
ignored katalogu z głównego projektu, obcego/pre-existing worktree ani ścieżki bez takiego dowodu.
