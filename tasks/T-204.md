# T-204 — Każdy terminal prezentuje właściwy bieg i zwalnia zamknięty stan

T-155 kończy backendową tożsamość wielu biegów, ale dzisiejszy frontend nadal ma globalne
`going`, sesję kluczowaną folderem i cache kontekstu, który spóźnioną odpowiedzią może nadpisać
inną kartę. T-156 zamyka zasoby native, lecz świadomie nie dotyka Reacta ani modułowych rejestrów.
Ten task podpina prawdziwe okno do adresowanego IPC i nadaje frontendowemu stanowi jeden pełny
klucz: terminal, canonical workspace, run UUID i physical step UUID.

**Zależy od:** T-154, T-155 i T-156.

## Kontrakt frontendowej tożsamości

Manualny Start wybija UUID v7 istniejącą rustową mennicą bezpośrednio przed `run_workflow` i
wysyła `terminal_id`, workspace oraz UUID. Pierwsza typowana odpowiedź/linia z T-155 zwraca
canonical workspace i jest autorytetem dalszego klucza; frontend nie kanonizuje ścieżki sam.
Stop, Continue, Say, retry, resume, `/ask` i Close zawsze wysyłają terminal, canonical workspace
i run UUID. Brak pełnej tożsamości jest widoczną odmową, nie fallbackiem do globalnego biegu.

Stan biegu jest per `(terminal, canonical workspace, run UUID)`. Kontekst agenta dodaje
`physical step UUID`; nazwa kafelka ani logical step id nie wystarcza, ponieważ kopie i rundy
pętli mogą mieć tę samą etykietę. Zdarzenie innego runu lub terminalu nie trafia do aktywnego
feedu. Dwa terminale wskazujące ten sam workspace mają jeden backendowy bieg, lecz feed i
kontrolki dostaje wyłącznie `owner_terminal`.

## AC-1 Kontekst jest kluczowany runem i fizycznym krokiem
check: npx --no-install vitest run src/sections/run/session/t204-context-is-keyed-by-run-and-step.test.tsx
expect: (\d+) passed

Target montuje prawdziwy `AgentScreen` oraz produkcyjny IO/cache i kontroluje kolejność Promise.
Odczyt A startuje, potem B; B kończy pierwszy, A ostatni, a ekran pozostaje przy B bez handoffów,
notatek ani manifestu A. Następna scena uruchamia nowy run w tym samym workspace i powtarza
logical step w dwóch kopiach: wynik starego runu ani sąsiedniego physical step UUID nie może
nadpisać nowego. Błąd bieżącego żądania daje pusty bieżący stan i angielskie zdanie, nie cache
poprzednika.

Target dochodzi przez prawdziwy mount i przełączenie zaznaczonego kroku. Nie woła cache helpera
bezpośrednio i nie podaje komponentowi klucza, którego produkcyjny caller nie ma.

## AC-2 Dwa workspace'y pracują i zatrzymują się niezależnie w prawdziwym UI
check: npx --no-install vitest run e2e/tests/t204-two-workspaces-run-independently.spec.ts
expect: (\d+) passed

Spec otwiera terminal A, startuje bieg, przełącza na workspace B i startuje drugi. Obie karty
mają własną live dot, feed, liczbę agentów oraz różne run UUID; powrót do A pokazuje wszystkie
jego linie. Pełna globalna pula pokazuje na C angielskie Waiting, a po zwolnieniu slotu ten sam
zarezerwowany run startuje automatycznie bez busy-loopu i bez nowego UUID.

Stop B wysyła terminal B, canonical workspace B i UUID B, usuwa wyłącznie jego live state,
a A nadal postępuje. Stara komenda UUID B po rozpoczęciu nowej generacji B jest odmową widoczną
na właściwej karcie. Drugi terminal wskazujący workspace A nie duplikuje feedu ani kontrolek;
jego zamknięcie nie zatrzymuje A, a zamknięcie ownera wysyła dokładny adres biegu.

Globalne `going` znika. Pending/Waiting jest per run, prezentacja per terminal, a wspólny limit
pozostaje wyłącznie backendowym faktem T-155.

## AC-3 Produkcyjny Close ewakuuje frontend i stary async wynik go nie wskrzesza
check: npx --no-install vitest run src/sections/run/t204-closed-ui-state-is-evicted.test.ts
expect: (\d+) passed

Setki terminali otwartych i zamkniętych produkcyjnym handlerem wracają do baseline'u rejestrów
feedów, sessions, answers, kontekstu kroków, Waiting/pending oraz wpisów `/start`. Przełączenie
aktywnej, nadal otwartej karty zachowuje jej pełną historię; tylko Close jest granicą retencji.

Każdy rejestr ma jedną wspólną akcję eviction wołaną z prawdziwego Close po adresowanym żądaniu
backendu. In-flight context request i poll procesów niosą generation/identity; odpowiedź starej
generacji po Close jest odrzucana i nie odtwarza mapy. Poll procesów jest single-flight, a
spóźniona starsza odpowiedź nie może cofnąć nowszej ani wskrzesić martwego wpisu.

Ten AC zastępuje wyłącznie część T-71 wymagającą historii po zamknięciu terminalu. Historia
otwartych kart, przełączanie bez utraty i izolacja per terminal pozostają.
