# T-129 — Bieżący katalog pamięci mówi o limicie, zasięgu i pochodzeniu

T-139 wylądowało pełny adres `{ place, id }`, dwa fizyczne korzenie i prawdziwe mutacje.
Pozostała bieżąca połowa H17: `memory::notes::what_you_know` zwraca `Block::dropped`, lecz
`list_note_catalog_inner` tego nie konsumuje, ekran nadal obiecuje „every agent”, a jeden klucz
`from:` oznacza dziś zarówno nazwę importowanego projektu, jak i identyfikator biegu refleksji.

To zadanie opisuje wyłącznie **stan obecnego katalogu**. Nie odpowiada, co dostał zakończony
bieg, nie zmienia `MemoryRecord`, `run.json`, historii ani SQLite. Zamrożony rachunek
rzeczywistych odbiorców należy wyłącznie do T-130, które rusza po wylądowaniu tego zadania.

## Granice implementacji

`NoteWire` dostaje addytywny fakt `leftOut`: `true` wyłącznie dla notatki `in-use`, którą ten
sam `what_you_know` odłożył poza **bieżący** limit jej zakresu. Nie wyprowadzaj tego z sumy,
statusu ani pozycji. Długa notatka może wypaść, a krótsza za nią nadal wejść. Biblioteka liczy
legalne `everywhere` oraz `this-agent`, projekt legalne `this-project`; zakres `this-agent`
liczy się osobno dla znormalizowanego właściciela. Wynik przypina się do pełnego adresu, więc
bliźniaczy `id` w obu korzeniach nie dzieli stanu. `leftOut` nie jest „last run” ani trwałym
stemplem i nie wolno go zapisywać do pliku notatki.

Pochodzenie rozdziela się od adresu i od zasięgu. Kanoniczny front matter importu używa
`project:` na nazwę projektu, a `from:` zostaje identyfikatorem biegu, który zaproponował
regułę. Model, `NoteWire` i lustro TypeScript niosą oba fakty osobno jako `project` oraz
`from`. Stary import z `from:` wraz z kompletem `source`, `source_hash` i `app` czyta się jak
`project`, nigdy jak bieg; stare automatyczne kandydatki z samym `from:` czytają się jak bieg.
Nie ma migracji ani przepisywania plików przy odczycie. `NoteAddress { place, id }` pozostaje
jedynym adresem i żadne pole pochodzenia nie uczestniczy w mutacji.

Każdy bieżący wiersz mówi po angielsku prawdziwy zasięg: `Every project`, `This project` albo
`Only <agent>`. Biblioteczne legacy w `Earlier project notes` nie może powiedzieć `This
project` przed Move. Importowany projekt i bieg dostają dwa różne zdania; pełny surowy UUID
nie może wystąpić po etykiecie projektu. Lead strefy `In use` jest neutralny wobec mieszaniny
zakresów i limitu. Wiersz `leftOut` pozostaje w katalogu, ale mówi wprost, że obecnie nie
wchodzi do promptów z powodu limitu długości.

Bieżący ekran agenta pozostaje przybliżeniem z obecnego katalogu do czasu T-130, lecz nie może
już kłamać w prostym przypadku: `notesFor` wyklucza `suggested`, cudzy `this-agent` oraz
`leftOut`. Nie wolno nazywać tego zamrożonym rachunkiem ani używać słów „last run”.

## Uczciwy `before`

Przed `./verify.sh before` istnieją wszystkie trzy nowe targety. Nie importują nowych symboli:
Rust wywołuje obecne wejścia produkcyjne i asertuje serializowany `NoteWire`, a testy
TypeScript budują obecną wartość `Note` i dodają przyszłe pola przez strukturalny spread.
Każdy target ma się skompilować, uruchomić i paść na asercji brakującego zachowania lub
widocznego markupu. Brak modułu, błąd kolekcji, błąd TypeScript, `0 passed`, `#[ignore]` albo
niedopasowany test nie są czerwienią.

## AC-1 Katalog wylicza pominięte adresy i nie miesza dwóch rodzajów pochodzenia

check: cargo test --test t129_current_memory_catalog_truth
expect: (\d+) passed

Standalone target sadzi ręcznie nadlimitowy aktywny zbiór: długa reguła wypada, lecz krótsza
o późniejszym identyfikatorze wchodzi. Wymaga literalnych wartości `leftOut` zgodnych z
`Block::{used,dropped}` dla pełnych `(place, id)`, obu korzeni, bliźniaczego `id` oraz dwóch
różnych właścicieli `this-agent`. Prosta odpowiedź „cały zakres jest nad limitem” ma przegrać.

Ten sam target zapisuje nowy import i nową kandydatkę z biegu, po czym czyta pliki oraz drut:
import ma kanoniczne `project: Project X`, `project = Project X`, `from = null`; kandydatka ma
`from = <run>`, `project = null`. Osobne fixture dowodzą zgodności starego importu
`from + source + source_hash + app` oraz starej kandydatki z gołym `from`. Pełny adres pozostaje
`place + id`, bez udziału pochodzenia.

## AC-2 Człowiek widzi bieżący limit, prawdziwy zasięg i dwa pochodzenia

check: npx --no-install vitest run src/sections/memory/t129-current-memory-truth.test.tsx
expect: (\d+) passed

Test montuje prawdziwy `MemoryScreen` i jego produkcyjne `NoteRow` z notatkami wszystkich
zakresów, importem, kandydatką biegu, legacy oraz `in-use + leftOut`. Widoczny markup rozróżnia
`Every project`, `This project`, `Only Forge`, projekt importu i bieg. Legacy przed Move nie
twierdzi `This project`; lead nie obiecuje „every agent”; pełny UUID nie udaje nazwy projektu.
Wiersz pominięty pozostaje widoczny i jednoznacznie mówi, że obecnie nie trafia do promptów z
powodu limitu długości. Asercja na helperze albo testowy props omijający prawdziwą sekcję nie
spełniają kryterium.

## AC-3 Bieżący ekran agenta nie pokazuje notatki odłożonej przez limit

check: npx --no-install vitest run src/sections/run/session/t129-left-out-is-not-given.test.tsx
expect: (\d+) passed

Test mockuje wyłącznie istniejący transport `list_notes`, woła produkcyjne
`readWhatWasGiven` i montuje prawdziwy `AgentScreen`. Agent widzi wpuszczoną notatkę globalną
oraz własną, ale nie widzi kandydatki, notatki innego agenta ani `leftOut`. Kontrola montuje
`MemoryScreen` i nadal widzi ten sam pominięty wiersz: wykluczenie z `Given` nie może zostać
zrealizowane przez skasowanie go z katalogu.
