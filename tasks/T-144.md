# T-144 — Recovery ma jedno wyjście i pełny dowód po zamkniętym T-141

Świeży standalone następca zamkniętego T-141. T-141 po jedynej rundzie naprawczej miało
zielone pełne testy oraz oba AC, ale pozostało 17/18 przez drugi `needless_raw_string_hashes`
w nowym specu. Gałąź jest dowodem, nie źródłem do lądowania w całości.

T-144 przejmuje pełną semantykę T-141 i trzy uwagi recenzenta we własnych, globalnie
unikalnych targetach. Po własnym uczciwym `before` wolno selektywnie zastosować wyłącznie
commity `bd5e42b`, `9ec7025`, `7ad1b70` i `36507aa`. Nie przejmuj `TASK.md`, commitów speców
T-141 ani całej gałęzi. Stary-boot/no-PGID zaimplementuj w bieżącym kontrakcie; commit
`d5f2797` miesza produkcję ze starym targetem T-141 i nie jest dopuszczony do cherry-picku.

`RunSpec.resume` zostaje jawnym transportem adapterów, nie recovery.

**Read first:** `src-tauri/src/recovery.rs` · `src-tauri/src/commands/reconcile.rs` ·
`src-tauri/src/engine/drivers/{mod,claude,codex}.rs` · wskazane `recovery_*.rs` ·
`runs/T-141/review.txt` i `runs/T-141/repair.txt`.

## Kto to robi

- **Agent:** Codex przez jeden pełny bieg Harnessu, po zamknięciu T-141.
- **Druga opinia:** osobny Codex na innym modelu, tylko do odczytu; właścicielski wyjątek D3.

## AC-1 Recovery sprząta i oznacza wyłącznie faktycznie przerwane kroki
check: cargo test --test t144_recovery_cleanup_is_the_only_plan
expect: (\d+) passed

Target przez prawdziwe `rows_to_judge` obejmuje pełny zakres T-141 oraz obie luki recenzenta:

- brak/pusta sesja i `attempt = -1`/`i64::MAX` nie wpływają na decyzję;
- tylko `ready`/`running` dostają `failed`/`interrupted`, a ich run `interrupted`;
- running run zawierający wyłącznie skończony krok z pozostawionym PGID nie dostaje statusu;
- na starym boocie `pgid = NULL`, `0`, liczba ujemna i własny PGID Loadouta nadal prowadzą
  do oznaczenia kroku/runu bez żadnego reap i bez `unreadable`;
- te same nieużywalne PGID-y na bieżącym boocie nadal są odmową w `unreadable`, nie celem
  sygnału ani zgodą na oznaczenie;
- bezpieczne współdzielone PGID-y są deduplikowane i sprzątane raz; nieznany status pozostaje
  `unreadable`;
- serializowany plan ma wyłącznie `reap`, `run_status`, `step_status`, `unreadable`; drugi
  przebieg nad rozstrzygniętymi wierszami niczego nie robi.

Usuń z `RecoveryRow` i SELECT-a recovery tylko `session_id`/`attempt`; kolumny `steps`
zostają. Run wolno oznaczyć dopiero po co najmniej jednym `RowVerdict::CutOff`. Dla starego
bootu nie ma reap, więc PGID nie jest walidowany; dla bieżącego bootu walidacja pozostaje.

## AC-2 Resume jest jawnym transportem i nie wraca z recovery
check: cargo test --test t144_resume_stays_outside_recovery
expect: (\d+) passed

Przerwany wiersz z `agent_session_id` nie oddaje z `decide()` sesji, pytania ani efektu
wznowienia. Osobno `RunSpec { resume: Some(...) }` prowadzi przez produkcyjne kompozytory argv
do właściwego identyfikatora Claude'a i Codeksa, a `None` wybiera pierwszą turę. Target czyta
nagłówek `drivers/mod.rs` i wymaga pełnego sensu: jawny transport adaptera oraz recovery,
które go nie konstruuje — sama obecność napisu `RunSpec.resume` nie wystarcza.

## Uczciwe `before`

Oba nowe targety muszą kompilować się na dzisiejszym API i paść na asercjach zachowania przed
zastosowaniem któregokolwiek commita T-141. Żaden SQL bez `#` nie używa raw-string hashy.
Brak symbolu, targetu, kompilacji albo lint nie jest prawidłową czerwienią.

## Wyłączenia

Nie usuwać `RunSpec.resume`, `SessionRef`, argv resume ani kolumn `steps.agent_session_id` i
`steps.attempt`. Nie zmieniać eskalacji startup reaper, tabeli `memory`, `Absent`, `supersede`
ani `Kind`. Nie kopiować targetów T-141 i nie lądować jego gałęzi.
