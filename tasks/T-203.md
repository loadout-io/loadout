# T-203 — Zepsuta definicja nie ukrywa zdrowej biblioteki

Produkcyjne listowanie agentów i workflowów ma dziś semantykę all-or-nothing: jeden wadliwy JSON
albo Markdown kończy całe IPC błędem. Człowiek widzi pustą lub starą listę, zdrowe definicje
przestają być używalne, a wadliwego pliku nie da się wskazać do ręcznej naprawy, ponieważ nie ma
poprawnego `id`. Ten task wprowadza jedną typowaną odpowiedź dla obu półek i prawdziwą drogę UI,
która pokazuje bezpieczną nazwę problemu bez udawania zmyślonej definicji.

**Zależy od:** T-210, który ląduje wspólny stos T-202/T-210.

## Kontrakt wspólnego typu

Rust i TypeScript mają jeden generyczny union z wariantami `Healthy` i `DefinitionProblem`.
`Healthy.value` zachowuje dokładny dotychczasowy kształt `Agent` albo `WorkflowEntry` — adapter
nie zgaduje ani nie przepisuje pól definicji. `DefinitionProblem` niesie wyłącznie półkę,
bezpieczną nazwę pliku oraz zamkniętą kategorię problemu potrzebną do angielskiego zdania.
Nie wysyła absolutnej ścieżki, arbitralnego komunikatu parsera, fragmentu prywatnego pliku ani
zmyślonego `id`/name/workflow.

Każda półka ma dokładnie jeden produkcyjny spacer: agentów nadal skanuje utwardzony przez T-210
`library::agents`, workflowy ich istniejący loader. Wspólny rdzeń obejmuje union, normalizację
problemu i `healthy_only`; nie powstaje drugi skaner agentów w
`commands/agents.rs`. Wspólny rdzeń nie dostaje destrukcyjnego Delete: przenośne filesystem API
nie potrafi atomowo powiedzieć „usuń tę nazwę tylko wtedy, gdy nadal wskazuje inode, który właśnie
sprawdziłem", a osobny journal dla pomocniczego przycisku byłby nową maszyną stanów bez związku
z głównym blockerem. Produkcyjne listowanie IPC zwraca wszystkie warianty, a `healthy_only`
zasila Rustowych callerów, którzy potrzebują tylko poprawnych definicji. Problem z jednym plikiem
nie zamienia listy na pustą i nie może zostać ukryty przez `unwrap_or_default()`.

## AC-1 IPC zwraca zdrowe definicje i izoluje dokładny problem
check: cargo test --test t203_bad_library_definitions_are_isolated
expect: (\d+) passed

Tymczasowa biblioteka zawiera dwa zdrowe workflowy, dwóch zdrowych agentów, wadliwy JSON
workflowu i wadliwy Markdown agenta. Produkcyjne `list_workflows_inner` i unionowe wejście agentów
zwracają wszystkie cztery `Healthy` oraz po jednym `DefinitionProblem` z właściwą półką,
bezpieczną nazwą i kategorią. Kolejność jest deterministyczna. Żaden problem nie ma pól definicji.
Target serializuje wynik do dokładnego wire shape używanego przez skorupy Tauri; nie dotyka
prawdziwego `~/.loadout` tylko po to, by literalnie wywołać bezargumentową komendę. Rejestrację
komend nadal dowodzi produkcyjny golden IPC w pełnej bramce.

Po atomowym poprawieniu wadliwego pliku następne listowanie bez restartu zwraca `Healthy` i nie
zwraca starego problemu. Nieczytelny katalog jako całość nadal jest odmową całej operacji —
izolujemy wadliwy plik, nie udajemy, że brak dostępu do biblioteki oznacza pustą bibliotekę.

## AC-2 Zdrowi Rustowi callerzy nie znikają przez sąsiedni problem
check: cargo test --test t203_library_callers_keep_healthy_definitions
expect: (\d+) passed

Ta sama biblioteka przechodzi przez produkcyjne drogi wyboru agenta w rozmowie Lead, listowania
agentów dla skills oraz roster check workflowu. Każda widzi wszystkich zdrowych agentów dokładnie
raz, nie widzi `DefinitionProblem` jako zmyślonego agenta i nie zamienia wyniku na pusty. Naprawa
pliku staje się widoczna przy następnym odczycie. Target wywołuje realnych callerów, nie sam
`healthy_only`.

## AC-3 Człowiek widzi problem, a zdrowe pozycje nadal działają
check: npx --no-install vitest run src/sections/t203-bad-library-definitions-are-actionable.test.tsx
expect: (\d+) passed

Target montuje prawdziwe ekrany Agents i Workflows z produkcyjnymi store/IO. Nazwa każdego
wadliwego pliku i angielskie zdanie wskazujące właściwą półkę do ręcznej naprawy lub usunięcia są
widoczne. Problemu nie da się otworzyć, edytować, duplikować, uruchomić ani przekazać do ogólnego
Delete jako zmyślonego `id`. Zdrowy workflow i agent zachowują swoje prawdziwe kontrolki; ich
istniejące oracles Open/Run/Edit pozostają w pełnej bramce. Nazwa wadliwego workflowu liczy się
jako zajęta dla Create/Duplicate. Zapis agenta wylicza target jednym kanonicznym helperem w
`library::agents` i odmawia nadpisania istniejącego `DefinitionProblem`; frontend nie kopiuje
algorytmu sluga. Test nie montuje samego helpera i nie podaje problemu propsem, którego
produkcyjny caller nie ma.
