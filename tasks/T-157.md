# T-157 — Connection odmawia literalnego sekretu przed zapisem

Importer obu vendorów przyjmuje dziś dowolne MCP args i URL. Literalny token może więc zostać
zapisany w definicji Connection, a później trafić do argv lub konfiguracji procesu. Ta wada ma
małą, wspólną granicę: import odmawia formom, które z wysoką pewnością są poświadczeniem, i mówi,
aby zamiast wartości wskazać nazwaną zmienną środowiska.

Zadanie nie rozwiązuje wartości env, nie uruchamia drivera i nie redaguje evidence. Prywatny
transport rozwiązanych wartości należy do T-205. Tutaj polityka ocenia wyłącznie importowaną
definicję i mieszka w jednym wspólnym rdzeniu używanym przez adapter Claude'a i adapter Codeksa.

**Zależy od:** brak.

**Read first:** `AGENTS.md` niezmienniki 9, 19, 23 i 24 ·
`src-tauri/src/import/adapters.rs` · `src-tauri/tests/it/import_mcp_is_disabled_and_managed.rs`.

Przed zmianą dochodzi do prawdziwego zapisu wadliwych definicji, a test pada na asercji odmowy.
Brak targetu, błąd kompilacji, collection error, grep źródła albo test samego prywatnego helpera
nie są prawidłową czerwienią.

## AC-1 Connection nie przyjmuje sekretu w argumencie ani URL
check: cargo test --test t157_literal_connection_secrets_are_refused
expect: (\d+) passed

Oba produkcyjne adaptery odmawiają przed zapisem osobnym fixture'om z `--token value`,
`--api-key=value`, URL userinfo oraz po dekodowaniu i bez względu na wielkość liter parametrom
query o wysokiej pewności: `api_key`, `api-key`, `access_token`, `token`, `secret` i
`authorization`. Komunikat jest po angielsku, nazywa wyłącznie bezpieczny klucz lub flagę i mówi,
aby użyć nazwanej zmiennej środowiska; nigdy nie powtarza literalnej wartości.

Kontrole dowodzą, że nadal przechodzą bezpieczne package args, `--tokenizer`, zwykłe URL z query
takim jak `page`/`timeout`, ścieżka zawierająca słowo `token` oraz same nazwy env bez ich wartości.
Ta sama funkcja polityki rozstrzyga oba adaptery; test nie kopiuje listy zakazanych kluczy i nie
woła wyłącznie helpera.
