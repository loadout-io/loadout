# T-157 — Prywatne instrukcje i sekrety nie trafiają do argv ani evidence

Główny task jedzie przez stdin i środowisko procesu jest czyszczone poprawnie. Trzy boczne
drogi omijają jednak tę granicę: instrukcje Claude'a są w `--append-system-prompt`, literalny
sekret może siedzieć w MCP args/URL, a wartości rozwiązanych secret env nie należą do filtra
raw evidence.

Ten task wąsko zastępuje T-60 AC-1(d) dla transportu instrukcji Claude'a: `BRIEF` i instrukcje
agenta nadal docierają dokładnie raz i osobno od zadania, ale z aktualnym CLI mają uczciwie
zadeklarowany autorytet `framed-user`, nie udawany system prompt. Zastępuje też T-34 AC-1
wyłącznie dla raw evidence zawierającego rozpoznany sekret: takie bajty są redagowane, nigdy
byte-exact. Niesekretne evidence zachowuje granice T-156, a reszta T-34 i T-60 pozostaje.

**Zależy od:** T-155; T-154, T-151 i T-156 są domknięte tranzytywnie. Kolejność względem
T-155 jest konieczna, bo oba zadania aktualizują `docs/ARCHITECTURE.md`.

**Read first:** `AGENTS.md` niezmienniki 5, 9, 19, 23 i 24 · `tasks/T-34.md` ·
`tasks/T-60.md` AC-1(d) · `docs/ARCHITECTURE.md` §4 i §8 ·
`src-tauri/src/engine/drivers/{mod,claude,codex}.rs` · `src-tauri/src/evidence.rs` ·
`src-tauri/src/connections/runtime.rs` · `src-tauri/src/import/adapters.rs` ·
`src-tauri/src/engine/supervisor.rs`. Nie loguj żadnej realnej wartości z lokalnej konfiguracji.

**Sonda 2026-08-27, bez wywołania modelu:** lokalny Claude Code 2.1.247 przyjmuje realtime stdin
`stream-json` wyłącznie jako wiadomości user; system instructions wystawia przez flagi
`--system-prompt`/`--append-system-prompt` (oraz ukryty wariant `*-file`). Ten task nie będzie
udawał system-role na stdin. Świadomy kontrakt v1 to typowana koperta user-content z osobnymi
polami standing instructions i task, przesłana wyłącznie stdin; receipt nazywa tę degradację.
Jeśli vendor doda system frame na stdin, polityka może zostać podmieniona w jednym adapterze.

## Tryb wykonania

- **Agent:** Codex w osobnym worktree, bez `ship-task.sh`.
- **Druga opinia:** osobny Codex na innym modelu, read-only, ze szczególnym review granic
  prywatności; właścicielski same-vendor D3.
- Wywołania: `./review.sh --agent codex --reviewer codex`, a jeśli są uwagi, dokładnie raz
  `./repair.sh --agent codex --reviewer codex`. Nie uruchamiaj domyślnego agenta Claude.
- Pełna ręczna pętla. Wszystkie markery są fikcyjne i generowane w fixture.

## Uczciwe `before`

Targety uruchamiają wykonywalne atrapy CLI i enumerują argv, stdin, env, config, evidence,
`run.json` oraz wartości `Debug`. Nie wystarcza asercja na builderze ani grep źródła.

## AC-1 Instrukcje Claude'a są wyłącznie w stdin
check: cargo test --test t157_agent_instructions_use_private_transport
expect: (\d+) passed

Fake Claude przechwytuje prawdziwe argv i stdin pierwszej oraz kolejnej tury. Unikalne agent
instructions występują dokładnie raz w typowanej kopercie stdin jako pole oddzielne od taska,
nigdy w argv, publicznych liniach, błędzie ani logu. Decoder atrapy dowodzi kolejności i pełnych
bajtów obu pól. Receipt/manifest zapisuje `instructionAuthority: framed-user`, więc produkt nie
twierdzi, że vendor dostał system-role. Codex przechodzi ten sam sentinel jako kontrolę. Prompt
obrazowy również nie trafia do pliku tymczasowego.

## AC-2 Connection nie przyjmuje sekretu w argumencie ani URL
check: cargo test --test t157_literal_connection_secrets_are_refused
expect: (\d+) passed

Importer odmawia przed zapisem markerom w `--token value`, `--api-key=value`, URL userinfo oraz
parametrach query o wysokiej pewności (`api_key`, `api-key`, `access_token`, `token`, `secret`,
`authorization`). Zdanie mówi,
aby użyć nazwanej zmiennej środowiska. Bezpieczne package args, zwykłe URL i nazwy env nadal
przechodzą. Wspólna polityka mieszka w jednym rdzeniu obu adapterów, nie w dwóch listach.

## AC-3 Wartość secret env dociera tylko do środowiska dziecka
check: cargo test --test t157_connection_secrets_never_escape
expect: (\d+) passed

Fikcyjny sentinel jest rozwiązany z Connection i trafia do dziecka obu vendorów wyłącznie
przez env. Nie występuje w argv, runtime config, raw stdout/stderr evidence, publicznych liniach,
`Debug` ani `run.json`, także gdy narzędzie jawnie go wypisze i gdy linia przyjdzie w kawałkach.
Runtime config Claude'a jest publikowany atomowo, ma `0600`, kontrolowany katalog i jest
sprzątany. Zawiera tylko nazwy env, nigdy wartości. Redaktor zachowuje limity z T-156 i
kategorię błędu bez prywatnych bajtów.
