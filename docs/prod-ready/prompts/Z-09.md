# Z-9 — Zamiatacz: worktree, kopie, retencja, prune

Sprzątanie po biegach działa tylko dla biegu, który właśnie się kończy (commands/run.rs close_the_trees). Reconcile (commands/reconcile.rs) przepisuje run.json i strzela po pgid, ale nie tyka worktree ani gałęzi; nigdzie nie ma git worktree prune; kopia plikowa (How::Copy) nie ma żadnego sprzątania; nie ma retencji .loadout/runs. Zmierzone: urc-monorepo 87 katalogów work/, 89 worktree, 99 gałęzi loadout/*, 3,8 GB. Zbuduj: (1) przy otwarciu workspace'u (tam, gdzie biegnie odzyskiwanie) domykać drzewa biegów w stanie terminalnym tą samą isolate::finish i wołać git worktree prune; (2) po biegu w trybie kopii usuwać cwd kroku, gdy nie zostawił LeftInPlace; (3) komenda forget_run(folder, id) kasująca katalog biegu i jego gałęzie (ta sama ostrożność co forget_run_branches: odmowa przy wyjętej gałęzi) plus prosta retencja w Settings (N ostatnich albo wiek); (4) przy Starcie w podfolderze repo jedno zdanie Line::Problem: this folder is inside a git repository but is not its root, so the work will not land on a branch; (5) .loadout/ do .git/info/exclude projektu (nie do .gitignore człowieka). Testy w it dla każdego punktu; dla (1) fikstura z biegiem interrupted i osieroconym worktree.
