# Z-1 — Dowód śmierci obejmuje potomków spoza grupy

Zamknij lukę w niezmienniku 6: dowód śmierci kroku sięga dziś tylko grupy procesów lidera (engine/supervisor.rs, Supervised::stop, group_is_gone, prove_gone, reap_group; recovery.rs apply). Claude Code uruchamia każdą komendę narzędzia Bash w OSOBNEJ grupie procesów, więc cargo test, npm run dev albo claude -p odpalone przez agenta przeżywają Stop, timeout i reaper startowy przy death_proof: true. Dowód z produktu: bieg meetnotes 20260901-150035, krok Combine, binarium testowe żyło 9 godzin po anulowaniu.

Zrób to w supervisor.rs (jedyny dom kodu platformowego, niezmiennik 3): przed pierwszym SIGTERM zdejmij migawkę drzewa potomków lidera (ps -axo pid=,ppid=,pgid=, domknięcie przechodnie od pid lidera), zbierz zbiór pgid i pojedyncze pid procesów w cudzych grupach, prowadź eskalację TERM -> łaska -> KILL i pętlę dowodową ESRCH dla KAŻDEGO z nich, powtórz migawkę po SIGTERM (agent potrafi jeszcze forknąć w oknie łaski). Do środowiska dziecka dołóż dziedziczony znacznik LOADOUT_RUN=<id> i LOADOUT_STEP=<klucz> (lista PASSTHROUGH), po którym stop i reaper znajdą ocalałych niezależnie od pgid. W run.json zapisuj pgids: Vec<i32> obok pgid (addytywnie), a recovery::decide/apply niech sprząta po liście. Reaper ma odmawiać sygnału, gdy proces pod numerem nie ma znacznika (L-7, przewinięcie pgid).

Test: moduł w src-tauri/tests/it/, w którym dziecko lidera robi python3 -c 'import os; os.setsid(); os.execvp("sleep", ["sleep","300"])'; asercja, że przed poprawką stop() oddaje Dead przy żywym wnuku (test ma paść na starym kodzie), a po poprawce Dead pada dopiero, gdy wnuk nie odpowiada na kill(pid, 0). Drugi test: run.json po biegu niesie pgids, a reap po restarcie zabija proces ze znacznikiem LOADOUT_RUN mimo innego pgid. Nie ruszaj sterowników poza tym, co potrzebne do przekazania znacznika. Popraw komentarze w drivers/claude.rs i drivers/host.rs, które przypisują sieroty hakom gospodarza.

## Kryterium akceptacji (z audytu 2026-09-02)

wykonania, dopiero potem właściwa implementacja. Jeśli nowy test wymaga nowego API, a inny test
regresyjny nie — rozdziel je, żeby ten drugi dało się uruchomić na starym drzewie.

**2. Ujednolicasz zachowanie — wymień WSZYSTKIE drogi, nie tylko nazwane w zleceniu.** Weryfikator

kroku, nieudany start, oraz `Drop` uchwytu. Dla stanu biegu: sukces, porażka, anulowanie, panika.
Droga, której nie ruszysz, jest tą, o którą zapyta.

**3. Jeśli z tej pracy powstaje ZDANIE, które czyta człowiek — asertuj je tam, gdzie ono stoi.**

komendę, której używa okno (`read_run_inner` i pokrewne), nie pole struktury.
