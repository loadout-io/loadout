# Z-7 — finish nie kasuje commitów agenta

commands/isolate.rs finish sądzi nic nie zmienił po samym git status --porcelain i przy pustym wyniku robi worktree remove oraz branch -D — agent, który sam zacommitował całą pracę na gałęzi loadout/<bieg>/<krok>, traci commity (nieosiągalne bez fsck). Obok touched() zadaje właściwe pytanie (status LUB rev-list --count base..HEAD). Przenieś tę logikę do finish: base z markera .isolation/<klucz> (pole head), czyste drzewo z commitami ponad base -> Kept::OnABranch bez nowego commita; branch -D tylko, gdy ani zmian, ani commitów. Przy okazji porażki remove_tree i branch -D loguj na warn i dopisuj do row.error, nie debug. Test w it (obok finished_runs_leave_no_work_trees): krok, którego proces robi git add -A && git commit w swoim worktree; po biegu gałąź istnieje, commit jest osiągalny z niej, historia biegu ją wymienia. Na starym kodzie test ma paść na braku gałęzi.

## Kryterium akceptacji (z audytu 2026-09-02)

Agent commituje wszystko sam i zostawia czyste drzewo → gałąź kroku zostaje (Kept::OnABranch), commit osiągalny, historia ją pokazuje.
