# Loadout 0.3.0 — runs you can believe

The first release after two audits and two repair passes. 0.2.2 could run a graph of agents.
This one can tell you the truth about what happened in it.

Version 0.2.3 was stamped but never shipped. If you are coming from 0.2.2, everything below
is new to you.

## Before you update

**QA steps will ask macOS for permission.** Checking whether a tested app has a window at all
talks to System Events through an Apple event, so the first such step brings up the Automation
prompt. Without it the result reads "not measured" rather than "failed", which is correct and
useless. The 0.2.x builds were signed with no entitlement at all, so this feature was dead on
your machine no matter what you granted.

**Updating is manual.** Loadout does not download or install new versions. Get the DMG, check
its SHA-256 against the one below, drag the app to Applications.

**Your files stay where they are.** The library format (`~/.loadout`), the workflow file format
and the run record did not change. Comparison sets saved by 0.2.x open without conversion.

## Runs tell the truth about what happened

- **A message sent while an agent is working gets through.** The turn queue belongs to Loadout
  now, not to the agent's app, and accepting a message and closing the queue happen under one
  lock. There used to be a window where a message was accepted and then handed to nobody.
- **The time ceiling belongs to the step, not to one turn.** A step with a six minute limit gets
  six minutes in total, across every turn, instead of six minutes each.
- **A recorded reason for a run ending beats a guess.** A run cut short by an infrastructure
  failure no longer reads as "unknown".
- **A kept working copy is a result, not a complaint.** A step that changed something in its own
  copy leaves the copy behind and says so in the result panel, with the step name and a button
  that opens the folder. That same sentence used to go into the error field and paint a green
  step red.
- **A refused start says why.** A run Loadout did not start explains itself instead of vanishing.

## Checks that actually check

- **A check step confirms the required tests by name**, streaming, and only from what the program
  wrote to standard output. A pass counter is not enough: two unrelated tests could stand in for
  thirteen required ones.
- **An approved list of requirements beats one word of summary.** The result comes from whether
  the list is complete, not from the word `pass` at the end of the prose. An unmeasured criterion
  is a third outcome: neither a pass nor evidence of a defect.
- **The "build, check, run, embed" template is data**, not a branch in the code.

## QA against the real application

- **A step tile says plainly that it launches an app with its own window**, and the test instance
  writes to its own data, not to yours.
- **The window is confirmed before QA starts**, and every action addresses one process by its
  identifier rather than by application name. Addressing by name hits whatever the window manager
  happens to point at, which can be your real app with your real data.
- **No route to the window means "not measured"**, enforced in code rather than asked for in a
  prompt.
- **A neighbouring repository is named before the first process starts**, together with both ways
  out.

## Agents written from a description

- **"Create with Claude" and "Create with Codex"** each return a draft written by the vendor you
  picked, in isolation: read only, no network, empty working directory.
- **The draft opens in the editor you already know**, and correct configuration and verified
  behaviour stand separately on screen.

## From the production pass — 215 changes since 2 September

What you can see from the window:

- Stop works per folder and reaches process descendants, including after an app restart.
- The lead can stop a run, and you can interrupt the lead while it works.
- A finished run keeps its tiles, and a run card tells the truth about what was left behind.
- Token and cost accounting, with an honest "price unknown" for models without a price list.
- Run results land on a branch shaped the way your repository shapes branches.
- The Linear integration key lives in an environment variable, not in a file.
- The Skills section has one read path from disk: what you see is what is in the agent folders.
- A project folder reached through a symbolic link works. Every part of Loadout now spells the
  project one way, computed once.

## Known issues

Two, both written down in `docs/KNOWN-DEFECTS.md`.

**An answer clicked at the exact moment a run ends does not appear under its question.** The
answer does reach the run and is in its record on disk; only the screen is wrong, until the run
history is read again.

**The notarisation ticket is stapled to the disk image, not to the app inside it.** With a network
connection you will not notice: Gatekeeper checks with Apple and accepts. A first launch with no
network may refuse.

## Verify your download

```bash
shasum -a 256 ~/Downloads/Loadout_0.3.0_aarch64.dmg
spctl --assess --type open --context context:primary-signature -v ~/Downloads/Loadout_0.3.0_aarch64.dmg
```

The first command has to print the checksum published with this release. The second has to answer
`accepted` and `Notarized Developer ID`.
