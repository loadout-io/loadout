# Loadout 0.6.2 — the import delivers what you ticked

Found by running a real import and reading what landed: six connections were ticked and four
arrived, and one agent came over out of thirteen. Nothing on screen said so.

**A connection you turn on is imported.** A tool server can be declared inside an agent's own
header rather than in the project's shared file. Loadout pins it to the first file that names
it, and dropped it whenever that file was left out of the import — before it ever looked at
whether you had turned the connection on. Your tick now decides. The tick row also names the
file the server was declared in, so a server riding on an agent you are leaving behind is
visible before you press Import.

**Project memory and a turn limit no longer hold an agent back.** An agent whose header carries
`memory:` or `maxTurns:` was marked "Needs a choice" and silently unticked, so it never came
over — a question whose two answers produce the same file. Such an agent now arrives ticked,
and its row says what Loadout does not carry across. An agent declaring `type:` still asks,
because that one really does change what gets written.

**The saved import file tells the truth.** The receipt in `imports/` recorded no filled agents
even when agents really had been given connections. It now carries the same list the window
names.
