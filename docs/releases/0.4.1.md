# Loadout 0.4.1 — workflow validation and accurate run results

- Steps that create or update a plan must be allowed to save it. The editor points to the
  incompatible step and offers an explicit **Ask first** fix; Run checks the same rule
  before starting any agent. Reading a plan still works with **Look only**.
- When a required plan is missing, dependent steps and previews are skipped. **Carry on**
  no longer causes a cascade of attempts that cannot start. Independent branches can finish.
- Run headers show the actual recorded outcome, including **Failed** and **Stopped**, with
  the recorded start and end times. An agent saying “Done” no longer hides a later failure.
- Repeated steps keep separate identities. Starting another workflow clears old results,
  and delayed events from the previous run cannot change its cards.
- Steps skipped without starting show **not run**. The agent count reflects processes
  actually started in this run. The final result survives a full transcript queue.

Updates are manual: download the Apple Silicon DMG and replace **Loadout.app** in Applications.
Your existing library and project data stay in place. Existing invalid workflows need their
permissions corrected; this update does not change permissions or replay failed work for you.

Validation checks the configured graph, required inputs and available permissions. It cannot
guarantee that an agent will produce a correct plan or working code; those results are checked
when the relevant step finishes. Live vendor compatibility checks remain separate from CI.

Both the application and DMG are signed and notarized. The release entry includes the source
commit, CI result and SHA-256 checksum.
