# Loadout 0.6.0 — agents arrive with their tool servers

An agent's Connections list decides which tool servers its session can reach. Until now that
list started empty and the only way to fill it was to type server names from memory, so agents
quietly ran without the tools you had already set up.

**New agents start with what this project has.** Press ＋ Create, and the Connections field
already carries every connection turned on in this project's library. The three ready-made
agents on the first screen get the same treatment the moment you take one.

**Connections are picked, not typed.** The Connections row in More settings is now a list of
what your project actually has. A name an agent carries that this project does not know stays
visible and marked, so you can take it off instead of discovering it when a run refuses to
start.

**Import hands its connections to the agents it brings.** Both import paths — Import in the
Agents section, and Import setup from project — now give the connections you turned on to every
agent that named none of its own, including agents already saved in this project. An agent that
already names connections keeps exactly those. After the import, Loadout says which agents got
which connections.

**Your own connections start turned on.** Connections found in your personal Claude Code
settings arrive ticked, because they are already yours. Connections found in a project's files
still start off and wait for you, since a repository's settings can name any command to run.

**Writing an agent from a description no longer offers what cannot work.** The model is shown
only the connections that are turned on, by name. Previously it could propose a turned-off one,
which was accepted at save time and refused later, at start.

**Empty library says where to look.** A project with no connections yet explains where they
come from and opens the import for you, instead of leaving an empty field without a word.

To update, download the macOS Apple Silicon DMG and replace your existing application.
